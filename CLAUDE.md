## Architecture & Tech Stack
Monorepo using `pnpm` workspaces:
- `packages/shared` (`@ptc/shared`): Shared TypeScript types, Constraint Catalog (`H01–H21`, `S01–S13`), hard/soft evaluators, in-memory `Occupancy` helper, and Thai XAI message templates (`messages.th.ts`) so Client, Server, and Worker share identical validation results.
- `apps/server` (`@ptc/server`): Express + TypeScript + Zod + Drizzle ORM (`drizzle-orm/mysql-core`) + `mysql2` connecting to TiDB Serverless (TLS) or MySQL 8, Worker Threads for Agentic Pipeline (`Planner -> Solver -> Validator -> Repair`), ExcelJS + PDFKit (Sarabun font).
- `apps/web` (`@ptc/web`): React + Vite + TypeScript + Tailwind + shadcn/ui + `@dnd-kit/core` + Recharts (mobile-responsive).
- `scenarios/`: `Q01.json` ... `Q25.json` deterministic test datasets.
- `drizzle/`: SQL migrations generated by `drizzle-kit`.
- `tests/`: Unit tests and Q01–Q25 scenario verification tests.

## Core Design Principles
1. **Hard Constraint = 0 always**, verified by a Validator completely separate from the Solver.
2. **All Constraints are configurable** (`constraint_configs`: `hard | soft | off`, weight, JSON params) because scenarios can conflict (e.g., Q09 caps teacher consecutive periods at 3 Hard, while Core 1.3 allows 4 Soft).
3. **XAI explanations are deterministic** from the Constraint Engine (JSON `explanation` rendered via Thai templates), NOT generated by LLM.
4. **No class clashes at DB level**: `course_offerings` (input problem) is strictly separated from `schedule_items` (output solution), backed by `slot_occupancy` with a Unique Index (`uq_no_clash`).

### 2. Places
3. `departments`: `id` PK, `code` VARCHAR(20) UNIQUE, `name` VARCHAR(100) NOT NULL

## `slot_occupancy` Writing Rules
- Write 1 row per resource per period inside the same DB Transaction as `schedule_items`.
- Every teacher in `schedule_item_teachers` -> `teacher` row.
- Groups without subgroups -> `group` row; groups with subgroups -> always `subgroup` rows (whole-group subjects write both A & B; split subjects write only their subgroup).
- Rooms with `allow_multi_group = false` -> `room` row; multi-group rooms omit `room` row and validate total capacity in Validator.
- `fixed_blocks` must be written into `slot_occupancy` before Solver runs.

## Competition 7-CSV Dataset Mapping
- `timeslot.csv` -> `time_slots` (day, period, start-end, lunch/break slots)
- `student_group.csv` -> `student_groups` (group_code, name, student_count, unavailable_slots)
- `register.csv` -> `course_offerings` + `offering_groups` (1 row = 1 offering, supports combined groups)
- `subject.csv` -> `subjects` (subject_code, name, theory_hours, practice_hours, credits, required_room_type, consecutive/sequence metadata)
- `teacher.csv` -> `staff` (employee_code, full_name, unavailable_slots)
- `teach.csv` -> `teacher_subject_eligibility` (teacher x subject, optional group_id)
- `room.csv` -> `rooms` (room_code, name/building, capacity, room_type)
